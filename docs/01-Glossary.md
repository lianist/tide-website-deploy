# 01 — 용어 사전 (Ubiquitous Language)

> 출처: [`original/glossary.md`](original/glossary.md) 8개 용어 전량. **설명 원문은 수정하지 않았고**, 코드/DB 식별자 열만 새로 붙였다.
> 문서·코드·DB·API·커밋 메시지는 모두 이 표의 말을 쓴다. 같은 것을 두 이름으로 부르지 않는다.

## 용어표

| 이름 | 영어 | 코드/DB 식별자 | 설명 |
|---|---|---|---|
| 태스크 | TASK | `tasks` 테이블 · `Task` 타입 | 태스크란, 본 서비스가 생성, 수정 및 관리하는, 유저가 해야 하는 업무이다. |
| 맥락 | CONTEXT | (타입 없음 — 에이전트 입력 구성 개념) | 맥락이란, 보다 정확한 태스크 관리를 위한, 유저의 캡쳐 정보 및 본 서비스가 유지하고 있는 유저에 대한 태스크 정보의 집합이다. |
| 캡쳐 | SCREENSHOT | `capture` (요청 페이로드 전용 · **저장하지 않음**) | 캡쳐란, 유저가 유저의 화면에서 본 서비스로 어떠한 정보를 넘기기 위해 활용하는 수단으로, 화면의 일부에 대한 스크린샷이다. |
| 상태 | STATUS | `tasks.status` — `todo` \| `done` | 상태란, 어떠한 유저의 태스크의 진행상황 및 비고사항을 포함하는 정보이다. |
| 에이전트 | AGENT | `lib/agent/` 모듈 | 에이전트란, 유저의 캡쳐를 바탕으로 태스크 관련 정보(신규 내용, 수정사항 등)를 추출하는 시스템이다. |
| 대시보드 | DASHBOARD | `/dashboard` 라우트 | 대시보드란, 유저의 태스크를 모아둔 웹사이트 또는 웹뷰 페이지이다. |
| 푸쉬 | PUSH | (앱 담당 — OS 알림) | 푸쉬란, 유저가 캡쳐를 에이전트가 분석 완료했을 때 유저에게 주는 알림이다. |
| 태그 | TAG | `tags` 테이블 · `task_tags` 조인 | 태그란, 여러 태스크 들이 공유할 수 있는 하나의 속성(e.g., 소속된 프로젝트 등)이다. |

## 파생 용어 (원본에 없으나 개발에 필요해 정의)

원본 8개 용어만으로는 코드를 쓸 수 없어 추가한 것들이다. 원본 용어와 충돌하지 않도록 뜻을 좁혀 정의했다.

| 이름 | 영어 | 코드/DB 식별자 | 설명 |
|---|---|---|---|
| 작업 로그 | JOB LOG | `job_logs` 테이블 | 에이전트가 캡처(또는 메일) 한 건을 처리한 결과의 기록. 성공·실패, 캡처 요약, 관련 태스크, 되돌리기 가능 여부를 담는다. `AGT-8`이 요구하는 산출물이며 히스토리 화면의 데이터 원천이다. |
| 근거 | RATIONALE | `tasks.rationale` | 에이전트가 이 태스크를 왜 그렇게 만들었는지 설명하는 **한 문장**. 캡처 원본을 저장하지 않는 대신 남기는 유일한 흔적이다(`AGT-1`, 결정 기록 4번). |
| 모드 | MODE | `create` \| `complete` | 사용자가 어느 단축키를 눌렀는지. 생성 캡처인지 완료 캡처인지를 가른다(`CAP-2`). 에이전트는 이 값을 사용자가 밝힌 의도로 취급한다. |
| 소스 | SOURCE | `source_kind` 열거형 — `capture_create` \| `capture_complete` \| `mail` \| `manual` | 태스크 변동이 어디서 비롯됐는지. 히스토리 표시와 알림 출처 구분(`[메일]`)에 쓴다. `job_logs.source`(에이전트가 처리한 입력 — `manual`은 오지 않는다)와 `tasks.source`(생성 경로 — `capture_complete`는 오지 않는다. 완료 캡처는 태스크를 만들지 않으므로)가 한 타입을 공유한다. |
| 우선순위 | PRIORITY | `P0` \| `P1` \| `P2` \| `P3` | **요구사항의 개발 순서**를 뜻한다. 태스크의 중요도가 아니다 — 태스크에는 우선순위 필드가 없다. 혼동을 피하기 위해 UI 문구에서는 이 낱말을 쓰지 않는다. |
| 루프 | LOOP | `L-P0-01` 형태의 ID | 검증 가능한 최소 개발 작업 단위. [`06-Loop-Engineering.md`](06-Loop-Engineering.md) 참조. |
| 보기 | VIEW | (`L-P1-10`에서 정한다) | 대시보드가 태스크를 나눠 보여 주는 단위 — 오늘 · 전체 · 완료(`DASH-9`). 필터(태그)와 다르다: 보기는 **무엇을 할 때인가**로, 태그는 **어느 영역의 일인가**로 가른다. |
| 확인 필요 | NEEDS REVIEW | (`L-P1-11`에서 정한다) | 생성 캡처가 실패했고 사용자가 아직 처리하지 않은 작업 로그(`DASH-11`). **신뢰도가 낮은 결과가 아니다** — 그런 개념은 두지 않는다(결정 기록 2). |

## 이름 규칙

- **DB·API는 영어 스네이크케이스**(`job_logs`, `due_at`), **TypeScript는 카멜케이스**(`jobLogs`, `dueAt`). 경계에서 한 번만 변환한다.
- **"Ttabong 전용"이라는 이름은 두지 않는다.** 앱은 `API-1` 계약의 한 클라이언트일 뿐이다.
- 사용자에게 보이는 문구는 위 표의 **한글 이름**을 쓴다("태스크", "태그", "캡처").
