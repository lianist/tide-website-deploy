## 1. 웹뷰 로그인 이어주기 🔴 — 2026-09-25 배포

### 무슨 버그였나

QA 보고: *앱에서 Google로 로그인 → 브라우저로 튕김 → "Google 로그인에 실패했습니다" → 다시 누르면 브라우저에서만 로그인되고 앱은 로그아웃 그대로.*

원인은 앱에 **로그인이 두 벌** 있다는 것이다.

1. 앱 로그인(`/auth/app/start` → `dochi://` → `/auth/app/token`)은 **앱의 토큰**만 만든다.
2. 대시보드 웹뷰는 **자기 쿠키**로 로그인해야 한다. 쿠키가 없으니 `/dashboard` → `/login`으로 밀리고, 사용자는 웹 로그인을 한 번 더 한다.
3. macOS에서는 그 웹뷰의 "Google로 계속하기"가 성립하지 않는다. 웹뷰가 Google 로그인을 시작하면서 **검증용 쿠키를 웹뷰에** 저장하는데, Google이 내장 웹뷰를 막아서 앱이 흐름을 시스템 브라우저로 넘긴다. 로그인은 브라우저에서 끝나고, 브라우저에는 검증 쿠키가 없어 **첫 시도는 반드시 실패**한다. 두 번째 시도는 처음부터 브라우저에서 돌아 성공하지만, 로그인되는 것은 **브라우저**다. 웹뷰는 끝까지 로그아웃 상태다.

웹 쪽만 고쳐서는 해결되지 않는다. 앱이 가진 로그인을 웹뷰에 건네야 한다. 그래서 그 통로를 열었다.

### 새 API — `POST /api/v1/web-session`

앱 토큰(Bearer)으로 부르면 **웹뷰용 일회용 로그인 주소**를 준다. 웹뷰에서 그 주소를 열면 로그인된 채 대시보드(또는 지정한 곳)에 도착한다. 정본은 api.md §`POST /api/v1/web-session`이다.

```jsonc
// 요청 (본문 선택)
{ "next": "/history?log=<jobLogId>" }
// 응답
{ "data": { "url": "https://dochi-six.vercel.app/auth/callback?token_hash=…&type=magiclink&next=%2Fdashboard" } }
```

### 앱이 할 일

1. **앱 로그인 직후** — `/auth/app/token` 교환이 성공하면 `POST /api/v1/web-session`을 부르고, 받은 `url`을 웹뷰에 `loadRequest`한다. **교환보다 먼저 부르면 안 된다**(교환 전 코드가 무효가 된다).
2. **웹뷰가 `/login`에 도착하면**(웹뷰 세션 만료) — 같은 호출을 한 번 하고 그 `url`을 연다. 무한 반복을 막으려면 한 번 실패하면 그대로 둔다.
3. 알림 클릭처럼 목적지가 정해져 있으면 `next`에 그 경로를 싣는다(`/history?log=…`).
4. 주소는 일회용·1시간이다. 저장하지 말고 필요할 때마다 받는다. 로그에 남기지 않는다.

이렇게 하면 웹뷰에서 로그인 화면을 볼 일이 사라지고, macOS의 Google 튕김도 같이 없어진다(웹뷰가 Google 로그인을 할 일 자체가 없어진다). Windows도 이중 로그인이 사라진다.

### 같이 바뀐 것

- 웹 주소 `/`가 더 이상 빈 "Dochi" 화면이 아니다. 로그인 흐름이 어긋나 거기 떨어지면 대시보드나 로그인 화면(실패 안내 포함)으로 보낸다. 앱이 할 일은 없다.

## 2. 보내 주신 피드백 넷 — 웹이 가져갔다 🔴

보내 주신 네 가지에 대한 답이다. **앱에서 지워도 되는 것이 셋, 앱이 할 일은 없다.**

### 1. 비밀번호 보기 토글 — 웹이 그린다 ✅

`/login`·`/signup`·`/reset-password/update` 세 화면의 비밀번호 칸에 자체 토글이 들어갔다. 브라우저가 얹어 주는 기본 눈 버튼은 웹 CSS가 숨긴다(`::-ms-reveal`·`::-ms-clear`) — 앱이 따로 숨길 필요가 없다.

- **누를 때마다 뒤집힌다.** 누르고 있는 동안만 보이는 방식이 아니다 — 키보드만 쓰는 사람이 `Enter`를 누른 채 읽을 수는 없어서다.
- 버튼의 접근 이름은 `비밀번호 보기` / `비밀번호 숨기기`이고, 상태는 `aria-pressed`로도 나온다. 자동화에서 잡을 때 쓰면 된다.
- **주입 코드를 지워 주세요.** 둘 다 남으면 눈이 둘로 보인다.

### 2. 단축키 철자 — 주신 표 그대로 ✅

| 플랫폼 | 지금 웹이 쓰는 문구 |
|---|---|
| Windows | `Ctrl+Shift+1` · `Ctrl+Shift+2` |
| macOS | `Shift+⌘+1` · `Shift+⌘+2` |

치환 코드는 이제 아무 일도 하지 않는다(정확히 일치할 때만 바꾸므로). 지워 주시면 된다.

**앞으로 이 문구를 바꿀 때는 먼저 알린다.** 요청하신 대로 우리 쪽 코드와 화면 명세에 "철자는 앱과 같아야 하고, 고치려면 앱 부서에 먼저 알린다"를 못 박아 두었다.

### 3. 좁은 폭 — 플랫폼을 골라 보게 했다 ✅

두 플랫폼을 나란한 열로 두던 것을 **한 번에 한 플랫폼**으로 바꿨다. 머리줄 `전역 단축키` 옆에 [macOS]·[Windows] 버튼이 있고, 줄은 예전처럼 둘(`새 태스크`·`완료`)이다. 좁은 폭에서 `새 태스크`가 쪼개지던 것이 사라진다.

- **처음 보이는 쪽은 웹이 요청 헤더로 고른다** — `Sec-CH-UA-Platform`(WebView2가 보낸다), 없으면 User-Agent의 `Macintosh`. 그래서 **Windows 앱은 Windows가, macOS 앱은 macOS가 먼저 보인다.**
- ⚠️ 웹뷰가 User-Agent를 직접 바꿔 쓰고 있다면 기본값이 틀어질 수 있다(틀려도 사용자가 버튼으로 한 번에 바꾼다). 바꿔 쓰고 계시면 알려 주시면 맞춘다.
- 고른 값은 저장하지 않는다 — 화면을 옮기면 다시 자기 플랫폼으로 돌아온다.

### 4. `← 대시보드로` 링크 — 웹에서도 지웠다 ✅

판단 요청 주신 건: **지웠다.** 인증 세 화면 어디에도 그 링크가 없다. 숨기는 코드를 지워 주시면 된다.

## 3. 작업 기록에 `handledAt` 한 칸

웹 대시보드에 **'확인 필요'** 목록이 생긴다. 할 일을 만들지 못한 캡처(할 일을 못 찾음·시간 초과·서버 오류)를 모아 두고, 사용자가 [직접 처리]로 태스크를 만들거나 [넘기기]를 누르면 목록에서 빠진다. 받은편지함처럼 비워 가는 목록이다.

그 "처리했다"는 표시가 `GET /api/v1/job-logs`의 각 기록에 한 칸으로 실린다.

```jsonc
{
  "id": "uuid",
  "outcome": "failed",
  "failureReason": "NO_TASK_TO_CREATE",
  "handledAt": "2026-09-25T02:10:00Z"   // ← 새로 생긴 칸. 아직 처리 안 했으면 null
}
```

- **앱이 할 일은 없다.** 모르는 키를 무시하도록 파싱하고 있다면 그대로 동작한다.
- 처리해도 **기록은 지워지지 않는다** — 목록에 그대로 있고 이 칸만 찬다. 앱의 히스토리 표시는 바뀔 것이 없다.
- 확인 필요에 드는 것은 **할 일 만들기 캡처의 실패 중 세 가지**(`NO_TASK_TO_CREATE`·`AGENT_TIMEOUT`·`INTERNAL_ERROR`)뿐이다. 중복(`DUPLICATE_TASK`)·완료 캡처의 실패·성공 기록은 늘 `null`이다. 그래서 이 칸만 보고 "확인이 필요한 기록"을 앱이 다시 가려내지 않기를 권한다 — 범위를 서버가 바꾸면 갈라진다.
- 이 값을 바꾸는 API는 없다. 처리는 웹 대시보드에서만 한다.

## 4. 새 주소 `tide-task.vercel.app` (옮기는 것은 선택)

보이는 이름이 **Tide**로 바뀌면서 웹 주소가 하나 늘었다.

| | 옛 주소 (그대로 동작) | 새 주소 |
|---|---|---|
| 서비스 | `https://dochi-six.vercel.app` | `https://tide-task.vercel.app` |
| API 베이스 | `https://dochi-six.vercel.app/api/v1` | `https://tide-task.vercel.app/api/v1` |
| 앱 로그인 진입점 | `…/auth/app/start` | 같음 |

- **앱이 할 일은 없다.** 옛 주소는 끊지 않고 리디렉트도 걸지 않았다 — 두 주소에 **같은 서버**가 떠 있다. 경로·요청·응답·에러 코드는 한 글자도 다르지 않다.
- 옮긴다면 **API 베이스와 로그인 진입점, 웹뷰가 여는 주소를 한꺼번에** 바꾸기를 권한다. 로그인 세션(쿠키)은 주소마다 따로라, 웹뷰만 새 주소를 열면 거기서 한 번 더 로그인하게 된다. 앱 세션을 웹뷰로 잇는 `POST /api/v1/web-session`이 돌려주는 주소는 요청을 받은 호스트를 따른다.
- 딥링크 스킴 `dochi://`는 그대로다. 사용자에게 보이지 않는 이름이라 바꾸지 않는다.
- 인증 메일(가입 확인·비밀번호 재설정)의 링크는 이제 새 주소를 가리킨다.

## 5. (참고) 웹 대시보드 화면이 바뀌었다

앱 웹뷰가 띄우는 화면이라 QA 때 달라 보일 것들이다. **앱이 할 일은 없다** — 알림의 [대시보드 바로가기](`/dashboard?task=<id>`)와 히스토리 주소는 그대로 동작한다.

- **사이드바 메뉴**가 `오늘 / 전체 / 확인 필요 / 완료 / 히스토리 | 설정`이 됐다. `/dashboard`를 열면 **'오늘'**(마감이 오늘이거나 지난 할 일)이 먼저 보인다. 미완료 전부는 '전체'다.
- 목록의 **동그라미를 누르면 완료·미완료가 바뀐다.** 상세 패널의 [할 일로]·[완료로] 버튼은 없어졌다.
- **'확인 필요'** — 에이전트가 할 일을 만들지 못한 캡처가 모이고, 남은 건수가 사이드바에 배지로 뜬다(위 3).
- 탭 제목·메일의 보낸 사람 이름이 **Tide**다.
