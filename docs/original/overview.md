#### 문제

#### 태스크 매니징이 까다롭다

- 무엇이?
    - 내가 직접 할 일을 매번 생성
    - 상태값을 매번 내가 직접 변경
- 왜?
    - 귀찮고
    - 병렬적인 프로젝트가 많아서
    - 다른 사람은 안 쓰고 나만 써봤자 공유가 안됨
    - 나이 많은 선배들이 노션을 사용하지 못함
    - ~~기존 툴은 개발자 중심이라서 내(마케터)가 쓸 수 없음~~
- 누가?
    - 저연차 실무자 마케팅 기획
        - 일단은 기획 파트 마케터
- 언제 가장?
    - 누가 질문을 해서 답변할 때
    - 지금 가장 급한 문제가 무엇인지 파악할 때

#### 솔루션

어디서나 편리하게 스크린샷을 통해 자유롭게 캡처한 사진에서 유저의 태스크 관련 정보를 추출하여 유저의 태스크를 자동으로 생성, 수정, 및 관리해주는 웹서비스

핵심: **“나 혼자 도입해서 나 혼자 잘 쓸 수 있어야 함”**

<aside>

### 사실과 가정

*본 프로덕트와 관련하여, 우리가 확신할 수 있는 사실은 무엇이 있고, 알지는 않지만 전제로 삼는 가정은 무엇이 있는가?*

---

#### 사실

1. 전역 단축키 기반 캡쳐 호출을 위해서는 데스크탑 클라이언트(플러터) 설치가 필수적이다.
2. macOS 및 Windows 환경에서 캡쳐 및 전역 단축키 기능을 구현하려면 유저가 직접 화면 기록 및 접근성을 명시적으로 허용해야 한다.

#### 가정

1. 유저는 업무 중 복잡한 태스크 입력 창을 직접 켜는 것보다 캡쳐를 사용하는 방법을 더 빠르고 직관적인 할 일 기록 수단으로 인지 및 선호할 것이다.
2. 비정형 화면(채팅창, 웹페이지, 캘린더 등)의 일부만 잘라내더라도 에이전트가 태스크를 충분한 정확도로 식별해낼 것이다.
3. 데스크톱 앱 설치라는 진입 장벽이 존재하더라도, 전역 단축키가 주는 편의성이 설치 번거로움을 우선할 것이다.
4. ~~유저는 캡쳐 후 매번 뜨는 태스크 제안 및 승인하는 팝업은 신뢰도를 높여주는 단계로 받아들일 것이다.~~
5. 에이전트가 캡쳐를 분석하고 태스크를 제안하는 과정은 최대 10초를 넘기지 않을 것이다.
