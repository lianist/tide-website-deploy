# 고정 캡처 평가 세트

`L-P0-08`(생성 캡처)과 `L-P0-09`(완료 캡처)의 검증에 쓰는 **고정된** 샘플 캡처다. 에이전트 프롬프트를 고칠 때마다 같은 사진으로 같은 경로를 돌려 회귀를 잡는다 — 매번 다른 사진으로 확인하면 좋아졌는지 나빠졌는지 알 수 없다.

폴더 하나가 **판정 경로 하나**이고, 폴더마다 `expected.json`이 그 안의 사진에 대한 기대 결과를 담는다.

## 실행

```bash
npm run grade                         # 생성 14건 + 완료 3건 1회 (실제 LLM, ≈ $0.02)
npm run grade -- create               # 생성만
npm run grade -- complete --repeat-each=3   # L-P0-09 게이트 — 3회 연속 전부 통과
```

실행기는 `e2e/grade/create.grade.ts`(생성)와 `e2e/grade/complete.grade.ts`(완료)이고, 공통 조각은 `e2e/grade/support.ts`다. **생성 실행기는 모든 케이스에 미끼 미완료 태스크 20건([`decoy-tasks.json`](decoy-tasks.json))을 먼저 깐다**(`L-P1-08`) — 후보가 있는 실사용 조건에서 지연을 재고, 미끼를 중복으로 묶으면 실패다. 판정은 그 캡처가 만든 태스크(`job_log_id`)만 센다. 케이스마다 새 사용자를 만들어 `existingTags`를 심고 에이전트를 돌린 뒤 **DB에 남은 것**을 아래 §비교 규칙으로 판정한다. 케이스마다 `[grade]` 줄에 실제로 나온 태스크·지연·토큰이 찍히니, 실패하면 거기부터 본다. `npm run test`에서는 돌지 않는다. 완료 실행기는 `seedTasks`까지 심은 뒤 돌리고, `[grade]` 줄에 닫힌 태스크 제목을 찍는다.

**튜닝에 쓰지 않는 보류 세트가 따로 있다** — [`holdout/`](holdout/README.md). 프롬프트를 고친 뒤 이 세트의 점수가 평가 세트보다 크게 낮으면 과적합이다. 그리고 **이 폴더의 정답 조각을 프롬프트에 싣지 않는다** — 누수 가드(`e2e/agent-create.spec.ts`)가 막는다.

장수를 더 늘리기보다 **지금 있는 것으로 먼저 돌려 보는 편이 낫다.** 어디가 약한지는 한 번 돌리면 드러나고, 그때 그 경로만 보강하면 된다.

## `expected.json` 스키마

```jsonc
{
  "mode": "create",              // create | complete
  "cases": [
    {
      "image": "01-....png",     // 같은 폴더 안의 파일명
      "source": "무슨 화면인지 한 줄",
      "capturedAt": "2026-09-20T19:15:00+09:00",  // 상대 날짜 환산의 기준 (AGT-4)
      "timezone": "Asia/Seoul",
      "existingTags": ["군무", "학업", "여행", "미분류"],  // 실행 전 DB에 심을 태그
      "expect": { /* 아래 */ },
      "note": "이 케이스가 무엇을 잡으려는지. 사람이 읽는다."
    }
  ]
}
```

### `expect` — 생성(`mode: create`)

```jsonc
{
  "outcome": "created",          // created | failed
  "failureCode": "NO_TASK_TO_CREATE",  // outcome이 failed일 때만 (NO_TASK_TO_CREATE | DUPLICATE_TASK)
  "taskCount": 2,                // 숫자, 또는 [최소, 최대]
  "tasks": [                     // **반드시 나와야 하는** 태스크들. taskCount와 별개로 검사한다
    {
      "titleMustMention": ["PPT"],      // 제목에 들어가야 할 조각
      "titleMustMentionMode": "all",    // all(기본) | any
      "dueAt": "2026-09-21",            // 또는 시각까지, 또는 null
      "dueAtOneOf": ["...", "..."],     // dueAt 대신. 둘 다 방어 가능한 날짜일 때만 쓴다
      "tags": ["학업"]               // 정확히 이 집합. 또는 아래 newTag
      // "newTag": true              // tags 대신 — 태그가 하나이고 existingTags에 없는 새 태그(이름은 안 본다)
    }
  ],
  "duplicates": []               // 중복으로 판정돼야 할 기존 태스크 제목. 생략하면 [] — 집합이 정확히 같아야 한다
}
```

중복 케이스는 케이스 수준에 `seedTasks`(완료와 같은 모양)를 함께 든다. 미끼보다 나중에 심어 후보 상한(최근 40건)에 밀리지 않는다.

### `expect` — 완료(`mode: complete`)

완료 캡처는 **고칠 대상이 DB에 미리 있어야** 성립한다. 그래서 케이스가 `seedTasks`를 함께 든다.

```jsonc
{
  "seedTasks": [                 // 실행 전 todo 상태로 심는다
    { "title": "ROKMC G6 Excel 문서 회신", "dueAt": "2026-01-26", "tags": ["군무"] }
  ],
  "expect": {
    "outcome": "completed",      // completed | failed
    "failureCode": null,         // 실패면 NO_TASK_TO_COMPLETE
    "completedCount": 1,         // done이 된 태스크 수. AGT-6이라 1 아니면 0이다
    "completedOneOf": [          // 이 중 하나가 닫혔으면 통과. seedTasks의 title을 그대로 적는다
      "연구 참여 동의서 작성해서 보내기"
    ],
    "unchangedCount": 3          // todo로 남아야 하는 태스크 수
  }
}
```

### 비교 규칙 — 여기가 이 파일의 핵심이다

LLM 출력은 결정적이지 않다. **문자열이 똑같기를 기대하면 평가 세트는 첫 주에 버려진다.** 그래서 검사는 이 세 가지만 한다.

| 무엇 | 어떻게 | 왜 |
|---|---|---|
| **개수** | 정확히, 또는 범위 | 판단이 갈릴 수 있는 곳은 범위로 연다 |
| **`dueAt`** | **명시된 정밀도까지만.** `"2026-09-21"`이면 날짜만, `"2026-09-21T08:30:00+09:00"`이면 시각까지 | `AGT-4`가 이 세트의 제일 중요한 과녁이다 |
| **제목** | 조각이 들어 있는지(부분 일치) | 표현은 흔들려도 **무엇에 관한 태스크인지**는 흔들리면 안 된다 |
| **닫힌 태스크** | `seedTasks`의 title과 **정확히** 일치 | 완료 대상은 우리가 심은 것이라 LLM이 문구를 지어낼 여지가 없다 |

`rationale`은 존재만 본다(`AGT-1`이 필수로 요구). 내용은 채점하지 않는다 — 문장이 매번 달라지는 것이 정상이다.

**`note`를 읽고 나서 프롬프트를 고칠 것.** 개수가 1이냐 2냐로 갈리는 케이스에 프롬프트를 맞추면 다른 케이스가 깨진다.

## 날짜 정책

`AGT-4`는 '내일', '금요일까지' 같은 **점 날짜**만 예로 든다. 그런데 실제 캡처에는 '이번 주 안에', '주말 중으로' 같은 **범위 표현**이 흔하다. 요구사항에 답이 없어 이 세트를 만들며 정했다. `L-P0-08`에서 프롬프트에 그대로 싣고, 바꿀 때는 여기와 프롬프트를 같이 고친다.

| 표현 | 마감 | 근거 |
|---|---|---|
| '이번 주 안에' (월요일에 받음) | 그 주 **일요일** | 마감일은 "언제까지"다. 범위라면 **허용되는 마지막 날**이 마감이다 |
| '주말 중으로' (금요일에 받음) | 그 주 **일요일** | 위와 같다. 주는 월~일로 센다 |
| '오늘 중으로' | **오늘** | |
| 아무 날짜도 없음 | **`null`** | `AGT-4` — 추측하지 않는다 |

**할 일과 무관한 날짜를 마감으로 삼지 않는다.** 파일 보관 기한, 행사 기간, 발신 시각은 마감이 아니다. 이걸 집어 오는 것이 `AGT-4` 위반의 가장 흔한 모양이라 `create/03-context-only/01`에 일부러 함정으로 넣어 두었다.

## 심어 둔 함정

경로를 채우는 것보다 **틀리는 방식을 미리 심어 두는 것**이 이 세트의 값어치다. 프롬프트를 고친 뒤 여기부터 확인한다.

| 어디 | 무엇에 걸리는가 |
|---|---|
| `create/02-multiple-tasks/02` | 번호 매긴 3개 항목 중 **하나는 안내**다. 번호대로 세면 과생성 |
| `create/03-context-only/01` | 파일에 붙은 **보관 기한**을 마감으로 읽는가 |
| `create/03-context-only/02` | **이미 답한 일**을 할 일로 만드는가 |
| `create/04-unrelated/01` | 아무것도 없을 때 **지어내는가** |
| `create/05-relative-date/03` | 노이즈가 많고 할 일은 조건부. **남의 할 일**까지 가져오는가 |
| `create/06-tagging/01` | 안 맞는 태그 대신 **새 태그를 만들어 버리는가** |
| `create/08-cold-start/` | 반대 방향 — 태그가 '미분류'뿐인 새 계정에서 **영역이 뚜렷한데도 '미분류'로 떨어지는가**(HF-10). 06과 짝이라 한쪽만 보고 프롬프트를 고치면 다른 쪽이 깨진다 |
| `create/09-second-area/` | 분야 태그가 하나 있을 때 두 번째 분야를 **'미분류'로 보내거나 그 하나에 억지로 넣는가**(HF-11) |
| `create/07-duplicate/` 1번 | 영문 캡처 ↔ 한국어 기존 태스크. **문자열이 달라도 같은 일**을 알아보는가 |
| `create/07-duplicate/` 3번 | 같은 프로그램·캡처에 나온 단어로 된 **다른 일**을 중복으로 묶는가(할 일 소실) |
| 모든 생성 케이스 | 미끼 20건 중 하나를 **엉뚱하게 중복으로** 묶는가 |
| `complete/01` | 같은 날 마감인 방해 태스크가 있다. **마감일로 고르는가** |
| `complete/02` | 셋에 걸리는 증거. **둘 이상을 닫는가** |
| `complete/03` | 완료 어투("리뉴얼되었습니다")에 끌려 **남의 완료를 내 것으로 닫는가** |

## 주의

- ⚠️ **저장소는 지금 private이지만, 공개로 돌린다면 이 폴더를 먼저 훑을 것.** 사진에 연락처·실명·소속이 찍혀 있다. 특히 두 장:
  - `create/02-multiple-tasks/03-newspaper-recruit-schedule.png` — 휴대전화 번호 3개와 이름·직책
  - `create/05-relative-date/03-kakao-dev-report-today-weekend.png` — 서비스 가입 코드. **실제로 쓰이는 코드라면 지금 바꾸는 편이 낫다**
- 이 사진들은 **테스트 픽스처이지 런타임 데이터가 아니다.** `AGT-10`("캡처 원본을 어디에도 저장하지 않는다")은 서비스가 받은 캡처에 적용되는 규칙이고, 여기 있는 사진은 평가용으로 직접 고른 것이라 충돌하지 않는다.
- 실제 LLM을 호출하는 평가라 **비용이 든다.** 장수를 늘릴 때는 호출당 비용(`03-Architecture.md` §설계 결정 4)을 함께 본다.
- `capturedAt`은 **정답의 일부다.** 상대 날짜(`내일`, `다음 주 월요일`)는 이 값으로만 풀리므로, 한 번 정한 뒤에는 바꾸지 않는다.
